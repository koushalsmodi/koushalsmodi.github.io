Agentic Systems

Learning note · LLMs, memory, tools, and planning

AI agents are systems that augment large language models (LLMs) with tools, memory, and planning. Instead of only answering a question, an agent can work toward a goal: decide what to do next, act on the environment, remember relevant context, and adjust its plan based on what happens. Reasoning models help with this, but an agent does not have to be built on a reasoning model to work this way.

Memory

Short-term memory is the context the agent is working with right now, such as conversation history and its current working notes. It is detailed but limited by the context window.

Long-term memory persists across sessions. It can hold facts, preferences, summaries of past work, and past decisions, often stored in databases or vector stores. Connecting to an external database is one way to implement it, not what defines it.

Retrieval-augmented generation (RAG) is closely related but not the same thing as long-term memory. RAG retrieves relevant external knowledge at run time, such as documents or records, and puts it into context. It can feed an agent's memory, but it does not by itself persist what the agent has learned.

Tools

Tools are how an LLM interacts with the environment, either to execute an action or to get data. Examples include search, code execution, APIs, and file or database access. The tool lifecycle is:

  • Tool creation: tools are usually provided by developers, though some systems can also generate new tools as code.
  • Tool definition: each tool is described for the model, typically with a natural-language description of what it does and when to use it, plus a function-calling JSON schema that defines its name and parameters.
  • Tool selection: the model chooses a tool based on those descriptions. When there are many tools, retrieval (for example, RAG over tool descriptions) can help narrow down the relevant ones first.
  • Tool calling: the model produces a structured call with the required arguments.
  • Tool output parsing: the model reads the result, including handling errors, invalid arguments, or unexpected output, and decides what to do next.

Planning and reflection

Planning is the agent's ability, after reasoning, to decide what action to take next and in what order. The degree of autonomy matters here: an agent may ask for approval before each action, act freely within set guardrails, or sit somewhere in between.

Reflection is the loop that checks that plan against reality. If a result is incorrect, incomplete, or a better path appears, the agent can correct itself, replan, and try a different approach. That usually means updating its plan, next action, or memory, not retraining or updating the model itself mid-task.
